# Битва методов оптимизации

Соколов Никита Константинович, группа К3339, поток 1.2.

## Комбинация и назначение

Грубая сетка и 32 воспроизводимые случайные точки дают восемь разнесённых стартов. Локальный метод Нелдера-Мида быстро уточняет кандидата. Затем метод ломаных Пиявского исследует два координатных сечения, причём второе проходит через уже улучшенную точку. Следующая локальная доводка уточняет обе координаты одновременно.

Если нужная точность не достигнута, резервный этап проверяет шесть направлений. Из каждого сечения сохраняются три разнесённых кандидата для локального поиска. Это помогает выйти из ловушки, когда лучший минимум на прямой ведёт в неверную впадину двумерной функции.

Интервалы Пиявского выбираются через очередь с приоритетом. Первичные оценки функции используются повторно, вместо отдельного дорогого оценивания константы Липшица. Точные повторы координат кэшируются без округления. Все методы реализованы самостоятельно, готовые солверы не используются.

## Тест и результат

Тестовая функция:

`f(x, y) = x² + y² + 20 sin²(πx) + 20 sin²(πy)`.

Это Растригин с параметром 10. Такая запись не теряет малые положительные значения при вычитании близких чисел. На области `[-5.12, 5.12]²` минимум находится в `(0, 0)`, значение равно нулю. Сетка содержит десять точек по каждой оси и не содержит ноль.

Замеры выполнены на Apple M5 Pro, macOS 26.6.2, Python 3.9.6. В таблице медиана 11 запусков с одинаковой функцией и seed 0. Время включает весь поиск и вызовы функции, но не импорт графических библиотек и построение рисунка.

| Вариант | Стандартная область, секунды | Ошибка на стандартной области | Ошибка на сдвинутой области |
| :--- | ---: | ---: | ---: |
| Исходный гибрид | 0.296771 | 3.52e-19 | 0.994959 |
| Только несколько локальных запусков | 0.001529 | 0.994959 | 0.994959 |
| Координатные сечения и локальный поиск | 0.000971 | 4.38e-18 | 5.91e-18 |
| Сечения с резервными направлениями | 0.000997 | 4.38e-18 | 5.91e-18 |

Выбран последний вариант. На стандартной задаче он примерно в 298 раз быстрее исходного и делает 635 вызовов функции вместо 49 250. На сдвинутой области `[-4.8, 5.3] × [-5.0, 5.1]` все 11 запусков успешны. На повёрнутом Растригине простой координатный вариант застрял, а выбранный получил ошибку 3.18e-17 за 0.003147 секунды.

Независимая серия из 100 случайных сдвигов и поворотов также достигла ошибки меньше 1e-12 во всех случаях. Подробности, разброс времени и исходные измерения находятся в [результатах сравнения](BENCHMARK.md) и [данных](benchmark_results.json).

## Условия и ограничения

Метод рассчитан на детерминированную конечную функцию двух переменных на ограниченном прямоугольнике. Производные не нужны. Оценка константы Липшица эмпирическая, поэтому конечный поиск не доказывает глобальную оптимальность произвольной функции. Узкие впадины, шум и очень дорогие вычисления могут ухудшить результат.

Ранний выход разрешён только при явно заданной достоверной нижней границе. Для демонстрации Растригина это ноль. Для неизвестной функции параметр `lower_bound` по умолчанию равен `None`, поиск выполняет весь бюджет и возвращает `search_complete`, а не обещание глобального минимума. В проверке стандартного Растригина без нижней границы время составило около 0.038 секунды.

## Предложенный критерий битвы

1. Сравнивается `err = f(x*) - f_opt`. Для указанного теста `f_opt = 0`.
2. Если `abs(err1 - err2) < 1e-6`, качество считается равным.
3. При равном качестве выигрывает меньшее время поиска, измеренное одинаково для всех участников.
4. При `err > 1e-2` результат не претендует на верхние места.

Финальный критерий утверждают преподаватели. Рекомендуется отдельно фиксировать число вызовов функции, а для устойчивой оценки времени использовать медиану повторов.
